# MyBTO — BTO unit ranker (HDB June 2026 exercise)

Live: https://mybto.vercel.app (target domain: mybto.sg)

Ranks every sale unit of the June 2026 BTO projects by each user's own importance weights.

| Type | Projects |
|---|---|
| Plus | Kebun Baru Breeze, Kebun Baru Ridge (Ang Mo Kio) |
| Prime | Berlayar Rise (Bukit Merah), Lakeview Cascadia (Bishan) |
| Standard | Sembawang Brook, Sembawang Portico (Sembawang), Woodgrove Acres (Woodlands) |

**Stack:** static site on **Vercel** (`public/`), **Firebase Auth** (optional email + password or Google sign-in; everyone else gets an anonymous user),
**Firestore** (each user's saved rankings with survey answers, and flags), and one Vercel function (`api/analysis.js`)
that computes the aggregate analysis with the Firebase Admin SDK.

## Data status: sample
- `public/data/units/*.json` is generated by `python3 pipeline/make_sample_data.py`.
  Berlayar Rise's unit list (blocks, storeys, unit numbers, flat types — 1,976 units) is real; every other attribute,
  and all units of the other six projects, are placeholders.
- Facilities at the 1st storey (void deck), including future amenities/facilities, are real for all seven projects
  (`pipeline/raw/facilities_1st_storey.json`, read off the HDB brochures); other facility values are placeholders.
- `lib/sample_submissions.json` (420 sample users, `npm run sample`) is mixed into Analysis so the charts have
  something to show. Turn off with `SAMPLE_ANALYSIS=0` in Vercel.
- The real-data pipeline (`pipeline/build_dataset.py`) builds the same JSON plus the Excel workbook
  (tabs Plus / Prime / Standard) from the reconciled brochure extractions in `pipeline/raw/`.

## Pages
`/` ranking (same as `/rank`) · `/shortlist` and `/analysis` (not linked from the header; opened in a new tab from the buttons above a ranking) · `/archive/home` (old home page) · `/archive/account` (optional sign-in, archived, not linked).
Inner pages are generated from one shell: edit `pipeline/build_pages.py`, then `python3 pipeline/build_pages.py`.
Images in `public/img/` are artist's impressions from HDB's June 2026 BTO brochures (© HDB), credited in the footer.

## Features
- **Rank**: project, one housing type, blocks, storey range and floor priority (higher / lower / none).
  Facings are only NE, SE, SW or NW. Equal scores share a rank and the next score gets the next number; minus
  scores are shaded below a red line. Importance −5…+5 per selected block,
  sun direction, 2-Room Flexi design and the other factors. Only factors that exist in the selected blocks are shown.
- **Survey**: the first press of Rank units (once per browser) opens a consent note and ten questions (age,
  who you will live with, application status, current home, BTO tries so far, work or study area, car, plans for
  children, household income, queue position; each has "Prefer not to say") (there is no queue number box). Every ranking after that is saved
  automatically with the answers and the full order of all matching units; the page shows only the top 50.
- **Shortlist**: ★ units into a separate list; reorder by drag or arrows. Synced to the account when signed in.
- **Account**: optional, so a shortlist and rankings follow you across devices. No email verification.
- **Analysis** (after the survey): min/max storey distributions with binomial fit and std, sun directions,
  blocks and factors ranked, floor preference, unit types, who ranked (survey answers), most shortlisted units,
  for all projects, by project type, project or unit type. Only rankings with a finished survey count.
- **Legend**: diagram + explanation for each factor.

Reference steps for a new project:
1. https://console.firebase.google.com → **Add project** (Google Analytics not needed).
2. **Build → Authentication → Get started → Sign-in method** → enable **Email/Password** (leave "Email link" off),
   **Google** and **Anonymous** (Anonymous is what lets visitors who don't sign in save rankings).
3. **Authentication → Settings → Authorized domains → Add domain**: your Vercel domain(s), e.g. `your-app.vercel.app`.
4. **Build → Firestore Database → Create database** → production mode → region `asia-southeast1` (Singapore).
5. **Firestore → Rules** → paste the contents of [`firestore.rules`](firestore.rules) → **Publish**.
6. **Project settings (gear) → General → Your apps → Web (`</>`)** → register an app → copy `apiKey`,
   `authDomain`, `projectId`, `appId`.
7. **Project settings → Service accounts → Generate new private key** → downloads a JSON file. Keep it secret;
   never commit it or paste it into chat.

### 2. Vercel
1. https://vercel.com/new → import this GitHub repo. Framework preset: **Other**. No build command.
   (Vercel uses `vercel.json`: output directory `public/`, functions in `api/`.)
2. **Settings → Environment Variables** — add for Production and Preview:
   `FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_PROJECT_ID`, `FIREBASE_APP_ID`
   (from step 1.6) and `FIREBASE_SERVICE_ACCOUNT` = the whole service-account JSON pasted as one value.
3. Deploy. Then add the deployed domain to Firebase **Authorized domains** (step 1.3) if you haven't.

## Local development
```
npm install
cp .env.example .env.local   # fill in the Firebase values
npm run dev                  # http://localhost:3000 (real Firebase)
npm run dev:fake             # no Firebase needed; analysis uses sample data only
npm test                     # unit tests (scoring + analysis)
node test/e2e.browser.js     # browser test of the full flow with Firebase stubbed (needs Playwright)
```
